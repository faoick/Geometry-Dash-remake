# Dash Rebuild

Независимый экспериментальный движок на Python / pygame-ce для Windows.
Цель проекта — постепенно воспроизвести Geometry Dash максимально точно,
с собственным исходным кодом и возможностью писать моды.

**Текущая версия — первый рабочий этап, а не полное воссоздание игры.**
Физика и столкновения ещё не проверены на точное совпадение с оригиналом.
Полное прохождение уровней не подтверждено. Редактора и совместимости с
Geode-модами пока нет.

## Запуск

Для другого компьютера отправляй **`release/DashRebuild-Windows-x64.zip`**.
Нужно полностью распаковать архив и открыть `DashRebuild.exe`.
Внутри уже есть Python и pygame-ce; устанавливать их отдельно не требуется.
Папку `_internal` нужно оставлять рядом с exe. Geometry Dash должна быть установлена
на компьютере получателя — её ресурсы в архив не включаются.

Для запуска исходников открой `Start.cmd`. Он проверяет работоспособность `.venv`,
а не только наличие файла python.exe. Если скопированное окружение не работает,
используется исправное `.runtime` или создаётся новое через системный Python 3.11+.
Установка зависимости при создании окружения требует интернета.
Обычная `.venv` привязана к базовой установке Python и не является переносимой сборкой.

Приложение самостоятельно находит Steam и папку игры. Можно указать путь вручную:

```powershell
.\.venv\Scripts\python.exe main.py --resources "C:\Program Files (x86)\Steam\steamapps\common\Geometry Dash\Resources"
```

Другой вариант — файл `resources-path.txt` рядом с exe или исходниками:
одна строка с полным путём к папке Geometry Dash либо Resources.
Неверный явно указанный путь теперь вызывает понятную ошибку, а не скрытый переход
к другой установке.

## Если запуск не удался

`user_data/launch.log` создаётся **до импорта pygame**, содержит начало запуска,
версию среды и полную ошибку. `user_data/crash.log` содержит последнюю пойманную
ошибку. При следующем успешном запуске старый crash.log может остаться: актуальное
состояние всегда смотри в launch.log. Для ошибок до запуска Python есть
`user_data/bootstrap.log` от Start.cmd.

Окно ошибки показывает причину и полный путь журнала. Если папка приложения
недоступна для записи, используются `%LOCALAPPDATA%/DashRebuild/user_data`, затем
`%TEMP%/DashRebuild/user_data`. Пришли launch.log и bootstrap.log для диагностики.
Сбои системного загрузчика до старта exe могут не попасть в Python-журнал.

Движок читает уровни, PNG-атласы, plist и музыку из локальной установки.
Записи в папку игры, загрузки в Steam и изменения оригинальных сохранений нет.
Код проекта написан отдельно; оригинальные ресурсы не становятся собственным кодом
и остаются внешней зависимостью.

## Что уже работает

- Меню Stereo Madness, Back On Track и Polargeist с реальными данными уровней.
- Собственные игровой цикл, столкновения, камера и отрисовка; оригинальный exe не запускается.
- Куб, приближённый корабль, базовые порталы, шипы, платформы, монеты,
  жёлтые площадки и сферы, синие гравитационные площадки.
- Исходные спрайты, фоновая музыка, базовые цветовые переходы.
- Пауза, повторные попытки, управление клавиатурой и мышью.
- Python-моды с событиями загрузки, сброса, клавиш и шага симуляции.
- Чтение всех 27 файлов уровней установленной версии. Чтение файла не означает
  поддержку всех его объектов и игровых режимов.

## Управление

| Клавиша | Действие |
| --- | --- |
| ← / → | Выбор уровня в меню |
| Enter | Играть / продолжить |
| Space, W, ↑ или ЛКМ | Прыжок; удержание для полёта |
| Esc | Пауза / продолжить |
| R | Начать заново |
| Backspace | Вернуться к уровням |
| M | Звук вкл. / выкл. |
| H | Показать хитбоксы — пример мода |
| N | Режим без смерти — пример мода |
| T | Скорость 0.5× без музыки — пример мода |

## Свои моды

Добавь файл `mods/my_mod.py`, затем перезапусти приложение. Пример:

```python
def on_reset(app):
    app.world.physics.cube_jump = 13.0

def on_key(app, key):
    pass

def on_tick(app, held):
    # Вызывается перед каждым шагом симуляции (240 раз в игровую секунду).
    pass
```

`app.world` содержит `player`, `level`, `physics`, `ticks`, `noclip`.
Настройки конкретной попытки нужно менять в `on_reset`, поскольку сброс создаёт
новый `World`. Доступен также `on_load(app)`. Ошибка отключает проблемный мод
и показывает сообщение. Это обычные Python-файлы, выполняющиеся с правами пользователя;
изоляции исполнения здесь нет. API пока экспериментальный.

Смотри готовый `mods/practice_tools.py`.

## Файлы проекта

- `core.py` — декодер уровней и физика без зависимости от окна.
- `assets.py` — поиск Steam и чтение атласов.
- `main.py` — интерфейс, ввод, звук, отрисовка и цикл приложения.
- `launcher.py` — ранний журнал, окно ошибки и запуск приложения.
- `build_portable.py` — сборка exe и ZIP с Python внутри.
- `modding.py` — загрузка модов и события.
- `test_engine.py` — проверки чтения данных, столкновений, порталов и повторяемости.
- `COMPATIBILITY.md` — ограничения, источники и план точной совместимости.
- `user_data/level_audit.json` — отчёт о файлах уровней.
- `user_data/crash.log` — последняя ошибка запуска, если возникала.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe main.py --audit
.\.venv\Scripts\python.exe main.py --smoke
```

Пересборка переносимого архива на Windows x64:

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller==6.22.3
.\.venv\Scripts\python.exe build_portable.py
```

В ZIP попадают исполняемый файл, runtime, пример мода и исходники в `source`.
Локальные логи, `.venv`, сохранения, чужие архивы и ресурсы Steam не упаковываются.

`--smoke` проверяет запуск, паузу и действия мода в SDL-окне без вывода на экран,
сохраняя снимки в `user_data`. Это проверка собственного приложения, а не
сравнение с оригинальной физикой.

Файл GD level string можно открыть через `--level-file путь\к\уровню.txt`.
Неизвестные ID отображаются предупреждением и розовыми метками;
полноценная поддержка современных уровней пока не реализована.
