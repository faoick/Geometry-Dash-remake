# Состояние совместимости — 12 октября 2026

Цель: самостоятельная реализация поведения Geometry Dash с максимально точной
физикой, исходными уровнями и расширяемостью. Текущая сборка — основа для этой
работы, а не достигнутое совпадение 1:1.

## Исходная установка

Проверена локальная Windows / Steam Geometry Dash, appid 322170,
Steam buildid 21578706. Данные берутся из `Resources/levels/*.txt`.
Содержимое сжатое: URL-safe Base64, затем gzip/zlib. У файлов 5002 и 5003
после завершающего NUL имеется байт 0xCD, который не относится к строке уровня.
Декодер останавливается на NUL, проверяет целостность сжатого потока и ограничивает
распакованный размер 32 МБ. Все неизвестные свойства сохраняются в словаре объекта.

Stereo Madness содержит 2 291 объект и 31 тип объектов в этой установке.
Уровни, музыка и графика читаются из Steam, не включаются в исходники проекта.
Исполняемый файл оригинала не декомпилировался; это собственная реализация
по формату данных и описаниям поведения. Никакой восстановленный исходный проект
RobTop здесь не заявляется.

## Что нельзя считать точным

- Начальная горизонтальная скорость взята из опубликованных измерений; на этой
  локальной сборке она независимо не измерялась.
- Прыжок куба использует предварительные коэффициенты: они требуют калибровки.
- Модель корабля использует опубликованные численные измерения для обычного размера.
  Вход в портал, границы коридора и порядок столкновений приближённые.
- Хитбоксы шипов — узкие прямоугольники; некоторые повёрнутые объекты используют AABB.
  Сложные столкновения, склоны и точный порядок обработки оригинала не восстановлены.
- Площадки, сферы, гравитация, вращение куба и камера реализованы приближённо.
- Присутствуют только куб и корабль обычного размера. Остальные режимы, dual,
  speed portals, mini, platformer и современные триггеры не реализованы.
- ID 22–28, 31–34, 62, 65 распознаются и скрываются, но их визуальные эффекты
  не воспроизводятся. Это отдельно отражено в JSON-аудите.
- Цветовые триггеры 29/30 дают линейный переход. Современные цветовые каналы,
  HSV, easing, эффекты входа, blending и точный порядок слоёв не поддержаны.
- Процент завершения основан на крайнем объекте плюс запас, а не исходном условии финиша.
- Музыка запускается с текущего времени симуляции; точная аудиозадержка не измерена.
- Успешный парсинг всех файлов не является доказательством игровой совместимости.
- Тесты не подтверждают полную проходимость ни одного оригинального уровня.

## Следующие этапы для максимальной точности

1. Получить эталонные траектории из оригинала: tick, input, x, y, vy, mode,
   gravity, grounded. Зафиксировать версию игры и настройки физики.
2. На коротких тестовых участках сравнить свободный прыжок, прыжок с края,
   приземление, удержание, столкновения и корабль с эталоном по каждому тику.
3. Уточнить hitbox-таблицы, порядок обработки контактов, импульсы и порталы.
4. Подтвердить Stereo Madness целиком одинаковой последовательностью нажатий
   в обоих движках. Проверить также намеренно неудачные нажатия.
5. Расширять проверку на следующие уровни; добавлять режимы и триггеры только
   вместе с эталонными примерами. Затем сделать совместимый редактор и сохранения.
6. Стабилизировать API модов и версионировать его. Переносимая сборка exe добавлена
   в 0.1.1; проверяется также запуск из распакованного ZIP без Python в PATH.

## Исправление запуска на другом компьютере, 0.1.1

Исходная `.venv/pyvenv.cfg` ссылалась на `C:\Python314`: копирование этой папки
не гарантировало запуск на другом компьютере. Это найденный дефект упаковки,
а не подтверждённая диагностика конкретного компьютера получателя.
Импорты pygame раньше происходили вне обработчика ошибок, поэтому ранняя ошибка
не могла попасть в crash.log. Теперь граница обработки стоит до импортов,
записывается заголовок запуска, включён faulthandler и есть резервная папка логов.

Переносимый ZIP содержит Python, pygame-ce и нужные DLL. Исходный launcher
проверяет скопированный интерпретатор и может создать новое окружение.
Прямой запуск main.py также проходит через ранний журнал.

Причина непереносимости venv описана в
[документации Python](https://docs.python.org/3/library/venv.html#how-venvs-work).
